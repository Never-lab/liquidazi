Note: Existing `screenAfterAuth()` stays in `introGate.ts` for post-login. Cold boot for **persisted** auth still uses rehydrate + whatever screen was saved; Task 2 adjusts persist so no-auth defaults to landing and logout sets landing. Helper documents the rule for tests and optional use in rehydrate.

Actually for cold start with **no** auth: initial state `"landing"`. For logout: `"landing"`. For `resolveColdStartScreen(null) === "landing"` and `resolveColdStartScreen({token:"x"})` used only if we normalize on rehydrate when screen is landing/auth oddly.

Simpler API matching tests:

```ts
export type EntryAuth = { token: string } | null | undefined;

/** Where to send a user with no intentional deep-link. */
export const doorScreenForAuth = (auth: EntryAuth): "landing" | "keep" =>
  auth ? "keep" : "landing";
```

Even simpler — stick to plan:

```ts
export const landingOrAuthDoor = (hasAuth: boolean): "landing" | "auth" =>
  hasAuth ? "auth" : "landing"; // WRONG - logged in shouldn't go auth
```

Correct:

```ts
/** Logout / signed-out door. */
export const signedOutDoorScreen = (): "landing" => "landing";

/** If rehydrating without auth, force marketing door (ignore stale game screen). */
export const normalizeScreenWhenSignedOut = (
  screen: string,
  hasAuth: boolean,
): string => {
  if (hasAuth) return screen;
  if (screen === "game" || screen === "setup" || screen === "menu" || screen === "intro") {
    return "landing";
  }
  if (screen === "auth") return "landing"; // cold door is landing now
  return screen === "landing" ? "landing" : "landing";
};
```

Cleaner:

```ts
export const screenWhenSignedOut = (): "landing" => "landing";

export const coerceSignedOutScreen = (screen: string): "landing" => {
  void screen;
  return "landing";
};
```

That's too blunt (would block viewing leaderboard while signed out). Spec: cold start and logout → landing. Signed-out users can still navigate to leaderboard from landing links.

```ts
/** Initial screen for installs / logout. */
export const SIGNED_OUT_DOOR: "landing" = "landing";

/**
 * After persist rehydrate: if no auth and screen is an in-app surface, send to door.
 * Allow public-ish screens: landing, auth, leaderboard, tutorial, guide, feedback.
 */
export const coerceScreenIfSignedOut = (
  screen: string,
  hasAuth: boolean,
): string => {
  if (hasAuth) return screen;
  const allowed = new Set([
    "landing",
    "auth",
    "leaderboard",
    "tutorial",
    "guide",
    "feedback",
  ]);
  return allowed.has(screen) ? (screen === "auth" ? "landing" : screen) : "landing";
};
```

Wait: on rehydrate, if someone left on `auth`, coerce to `landing` (door first). If left on `leaderboard` while guest, keep. Good.
